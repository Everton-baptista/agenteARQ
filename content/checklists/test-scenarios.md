# Test scenarios and personas

- [ ] Write at least one scenario per `AC-n` in `scenarios.yaml`, with kind and given/when/then.
- [ ] Cover failure or permission cases wherever they exist; ask the owner instead of inventing rules.
- [ ] Write `personas.yaml` from the brief and keep the adversarial personas.
- [ ] Map every scenario to a test in the product's stack, at the narrowest layer that proves it.
- [ ] Name the scenario id in each test; run automated accessibility checks with browser journeys.
- [ ] A healer may repair a locator, never an assertion; an unapproved assertion change is a finding.
