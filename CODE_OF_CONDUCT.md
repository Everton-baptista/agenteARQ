# Code of conduct

## The standard

Be respectful. Assume the other person is acting in good faith and knows something you do not.

That is the whole rule. Everything below is what it means in the places where it usually gets
tested.

## In technical disagreement

This project's contribution process is adversarial by design: `CONTRIBUTING.md` asks whether a
proposed control can actually fail, and `GOVERNANCE.md` asks who starts failing when it ships.
Those questions are meant to be hard. They are asked of the **proposal**, never of the person who
made it.

- Argue about the rule, the failure mode, and the evidence.
- "This control can never fire on a valid project" is a technical objection.
- "You clearly have not read the spec" is not one, and it is also usually wrong.
- If you are the one being pushed back on: a rejected RFC is a rejected RFC, not a verdict on
  you. Several of the rules in this repository exist because an earlier version of them was wrong
  and somebody said so.

## Unacceptable

- Harassment, insults, or personal attacks, in issues, pull requests, RFC threads or anywhere
  else the project is discussed
- Sexualised language or imagery, and unwelcome attention of any kind
- Publishing others' private information without explicit permission
- Sustained disruption: reopening settled decisions without new argument, or derailing threads
- Deliberately reporting a security issue in public to force a response

## Security reports

`SECURITY.md` asks for private disclosure through GitHub Security Advisories. Respect that
window. Publishing a working exploit against a project people have installed, to make a point
about response time, harms the adopters and not the maintainer.

## Scope

Project spaces — the repository, its issues, pull requests, RFC threads and discussions — and
public spaces when you are representing the project.

## Reporting

Report privately to the maintainer named in `GOVERNANCE.md`. Reports are handled confidentially.
If a report concerns the maintainer, say so in the report; GitHub's own abuse reporting is
available and is the right escalation when the person you would be reporting to is the problem.

This project has one maintainer, which is stated plainly rather than dressed up as a committee.
It means enforcement here is one person's judgement, and you should know that before you rely on
it.

## Enforcement

Depending on severity:

1. A private note explaining what was wrong.
2. A public correction in the thread.
3. A temporary block from participating.
4. A permanent ban.

Most things stop at step 1. Nobody has been through step 3 or 4, and the intent is to keep it
that way — but a code of conduct nobody would ever act on is decoration, and this project has
opinions about rules that carry no consequence.
